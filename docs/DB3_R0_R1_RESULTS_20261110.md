## R1: projection correction

Added `scripts/realsense_projection.py`, shared by the cleaner, candidate preparation,
bridge, R1 raw-depth previews and validation. Version names:

- `legacy_inverse_brown_v1`: historical baseline reproduction.
- `librealsense_2_59_1_v1`: exact pinned SDK convention for supported recorded models.

Unversioned old calibrations resolve to legacy. Unknown versions and mismatched
capture/calibration versions fail. Cleaner reuse refuses silently upgrading a
legacy dataset. The candidate bridge no longer monkey-patches `invert_brown`.

The SDK's inverse-Brown projection applies tangential terms after radial scaling;
the prior isolated candidate's ordinary Brown expression was approximate. The
new implementation follows the pinned executable and
[SDK source](https://github.com/realsenseai/librealsense/blob/v2.59.1/src/rs.cpp#L4012-L4164).
This convention should not be extrapolated to untested SDKs/models.

| Numerical check | Result |
|---|---:|
| Recorded RGB model: maximum SDK projection difference | 0.000204627 raw RGB px |
| Recorded RGB: maximum SDK deprojection difference | 0.00000138738 m |
| Recorded depth: maximum SDK projection difference | 0.000087959 px |
| Recorded depth: maximum SDK deprojection difference | 0.000000830152 m |
| Samples per recorded stream | 12,100 |
| Depth domain | 0.3, 0.7, 2.0, 5.9 m |
| Numerical compatibility gate | Passed, <0.1 raw RGB px and <1e-5 m |

The sample domain includes a 41×25 full-image/border grid and 2,000 seeded random
pixels at each depth. Tests additionally exercise none/Brown/inverse-Brown IDs,
coefficient order, scaled/cropped rays, extrinsics direction and column-major
layout. Pinned SDK is 2.59.1, wheel SHA256
`045dfae020a635ba0c2c27e79ea3fa844acb86101344f68ca4c4163beb94b721`.

Regenerated all 477 RGB images directly from the DB in a fresh directory. Kept
the original 834×463 output, K and `(7,7)` crop for comparison. Recomputed depth
from original source frames and proved every stored sample coordinate/depth
exactly equal to its historical baseline array. No old features, matches, poses,
clouds or trained weights were attached to the new RGB.

Nearest-Z grouping retains invalid/missing pixels and saves observed, missing and
multiple-projection masks per frame. Missing is unknown, not measured empty space.
Collision masks expose possible visibility issues; they do not independently
identify physical occlusions. Physical disocclusion classification needs the
later validated multi-view geometry. No depth hole filling was performed.

### Physical boundary checks and gate

| Reviewed static structure | Historical median distance to observed depth band | SDK median distance | Limitation |
|---|---:|---:|---|
| Kiosk pedestal outer contour, three rows | 7 px | 0 px | Depth band up to 9 px; one row contains a hole |
| Opaque box outer contour, three rows | 8 px | 0 px | Depth band up to 14 px; all rows contain holes |
| Exhibit head-top control, one row | 0 px | 0 px | 6 px band and missing samples; motion uncertainty |

Zero means overlapping intervals, **not zero physical alignment error**. Signed
depth-band-minus-RGB intervals, source IDs, annotation intervals and interior depth
measurements are saved per row. Regions were reused from the existing structure
inventory and reviewed in full context to distinguish silhouettes from texture.
The annotations are exposed single-analyst readings assisted by gradients; they
are not blind or independently replicated measurements.

The protocol's precise physical gate requires narrow valid transitions and
replicated annotations, with tolerance at least 2 px and larger where annotation
variability warrants it. Current broad/missing bands cannot satisfy that precise
gate. Local coarse compatibility supports the SDK candidate at the near opaque
structures; it does not establish a whole-frame or whole-scene physical pass.

Thin rails remain broader/fragmented in depth and are rejected as calibration
targets. Wide/far doorway ROIs have only 44.1%/14.8% projected depth coverage.
Glass, clipped exterior and near display-case holes remain unresolved. High-motion
head/box observations with rotation-gap estimates above 1 px are excluded from
precise alignment acceptance. No global image shift was fitted.

## R1: timing findings and decision

Audited 4,764 RGB, 4,764 depth, 31,758 gyro and 15,905 acceleration headers and
the per-frame metadata. All four header/database streams increase strictly;
database timestamps equal serialized image/IMU headers in this recording.
RGB/depth metadata both declare Global Time. Their counters increase without
gaps and retain a color-minus-depth counter difference of 10.

| Depth minus RGB timing field | Median | Range |
|---|---:|---:|
| Database/header | -7.24715 ms | -12.2024 to -2.8353 ms |
| Metadata global timestamp | -0.03394 ms | -0.03906 to -0.03198 ms |
| Device readout timestamp | -0.034 ms | -0.034 to -0.033 ms |
| Device exposure-midpoint timestamp | -3.292 ms | -12.423 to -0.431 ms |

The SDK defines Frame Timestamp as readout/transmit start and Sensor Timestamp
as the device-computed exposure midpoint, both in microseconds.
[Metadata definitions](https://github.com/realsenseai/librealsense/blob/v2.59.1/include/librealsense2/h/rs_frame.h#L15-L37)
Depth exposure varies from 962 to 24,944 us; color's per-frame Actual Exposure is
absent. Every nearest exposure-midpoint pairing agrees with the existing pairing.

**Decision:** keep the actual recorded pairs. A guessed 7 ms correction or a
neighboring-frame swap is unsupported. Preserve per-pair exposure timing and motion
uncertainty. The simple rotation scale `f × |gyro| × |sensor gap|` has median
0.330 px, 95th percentile 2.205 px and maximum 14.367 px at the prepared focal
scale. This is a diagnostic, not an integrated displacement or correction; it
omits translation, rolling shutter and unverified camera/IMU clock/extrinsics.
