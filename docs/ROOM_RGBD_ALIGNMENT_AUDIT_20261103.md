# Room RGB-depth alignment: initial dense-depth audit

Date: 2026-11-03. Source: `20261030_134523.db3`. **Decision: inconclusive; the alignment gate has not passed.** The audit reconstructs and inspects six paired views, but does not yet supply independent, manually verified boundary correspondences or a defensible per-region error tolerance.

## What was done

`scripts/audit-room-rgbd-alignment.py` reads the original paired depth message for each selected image from the DB3 in SQLite read-only mode. It converts the stored values using 0.001 m/unit, deprojects with the recorded zero-distortion depth intrinsics, applies the recorded depth-to-color transform and prepared RGB intrinsics including crop, then projects into the prepared 834 x 463 image. It keeps the nearest camera-Z value per rounded target pixel, accepts 0.3–6 m sensor depths, and performs no hole filling or smoothing. A zero in the output `.npz` means no projected measurement. Projection gaps can arise from invalid sensor values, range clipping, disocclusions or sampling, not only from missing sensor data.

For each view, the corresponding [comparison image](../results/room_improve_rgbd_alignment_20261103/) shows prepared RGB; distance-colored unfilled projected depth (untinted means no projected sample); magenta discontinuities between adjacent valid projected depths; and cyan pixels retained by the baseline preprocessing before 16,000-point sampling. Its numerical depth map and [report.json](../results/room_improve_rgbd_alignment_20261103/report.json) are alongside it. Black in the *numerical map* is represented by zero; the RGB overlay leaves unsampled pixels untinted, not black. The training preprocessing additionally masks discontinuities and median-filters valid neighborhoods; it is not the unfiltered diagnostic map.

As a reproducibility check, the script reran the baseline `clean_depth` method on each depth message and matched all saved sampled pixel keys and their depths; maximum depth difference was 0 m in all six cases. This checks the audit against the existing processing code, not the physical correctness of calibration or alignment. The source file size and modification time were unchanged during the read.

Percentages are fractions of the prepared image receiving a projected sample in this implementation, not sensor accuracy or surface coverage. RGB-depth timestamp gaps for these six pairs are 6.23–7.51 ms. The script also records an exploratory distance from each detected depth jump to the nearest RGB Canny edge; it is unsigned and admits unrelated texture edges, so it **is not an alignment error** and is not a pass/fail metric. Differences between frames cannot establish a motion effect because their content and depth distributions differ.

## Calibration and limitations

The recorded depth intrinsics have zero Brown coefficients; depth units are 0.001 m. The preparation crops 7 pixels from each side of the 848-wide undistorted RGB and subtracts the same crop offset from the principal point, giving 834 x 463 and principal point approximately (419.225, 233.487). The depth-to-color transform is used in the same direction as the existing pipeline. Reproducing these operations is not an independent verification of the factory transform, crop mapping, timing, metric scale or sensor accuracy. No ground-truth depth or independent camera calibration was available.

There is no justified scene-wide pass/fail tolerance yet. No correction was applied, and no global alignment, time-offset or depth-reliability conclusion is warranted. Before using depth as reliable evidence, select multiple non-reflective, static edges with identifiable foreground/background boundaries at near, middle and far distances; annotate independent RGB and depth correspondences in these and additional frames, report signed displacement and uncertainty per region, and compare motion conditions on the same structures. Check candidates on held-out views before adopting any calibration or time-offset change. If suitable far boundaries have no valid samples, record the gate as unresolved there rather than inventing measurements.

No baseline model, source database or prepared dataset was changed; no training or pose repair was run.
